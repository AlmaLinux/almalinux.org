# AGENTS.md

Instructions for any AI agent working in this repository (Claude Code, Gemini CLI, Copilot, Cursor, Codex, and others). This file is the tool-neutral source of truth; `CLAUDE.md` and `GEMINI.md` simply import it.

If you are a human contributor who is new to this, an AI assistant pointed at this repository will read this file and help you follow these conventions. For project setup and the contribution workflow, see `README.md`, and ask in the Marketing SIG channel on chat.almalinux.org.

## What this repository is

The source for the **almalinux.org** website, built with [Hugo](https://gohugo.io/) (a static site generator). Content lives in `content/`, page templates in `layouts/`, styles in `assets/scss/`, and translations in `i18n/`. Every change is reviewed by a teammate through a pull request before it goes live, so experimenting is safe.

## Build, preview, and check

- **Preview locally:** `hugo server` (build with `hugo`). It needs Hugo (extended). If it is missing, offer to help install it.
- **Styles** are SCSS, compiled from `assets/scss/main.scss`.
- **After any visible-text or template change,** run `python3 find_missing_i18n_strings.py` to update `i18n/en.json` (NEVER edit directly)
- A husky pre-commit hook runs prettier on staged files (via lint-staged) when you commit, so keep changes prettier-clean. The hook activates after `npm install`.

## How to work here

- **Before making any suggestions to your user or committing anything, review all the documentation in this repository** (this file, `README.md`, and any other guides such as `DESIGN.md` and `contributing-blog-posts.md`) so your work follows the project's established conventions.
- Work on a **feature branch** and open a **pull request**. Never commit or push directly to `master`.
- **Confirm with the human before pushing or opening a pull request.** We like to keep the commit history as clean as possible.
- **Preview or verify a change before calling it done.** Never claim something works without checking it (build it, or check the rendered output).
- For anything bigger than a tiny fix, **propose a short plan to your user first** and wait for a yes.
- For any major design and content changes, have your user open an issue to discuss the change before doing any work.
- Follow the existing patterns in the codebase.
- If the contributor is new to code, explain in plain language and offer to preview results.

## Hard rules

- **Don't add AI attribution** to commits or pull requests, but do make a note that there was an AI assistance, so code and content can be appropriately reviewed.
- Commit messages are plain, capitalized sentences (no `feat:` or `fix:` prefixes).

## Text and translations (i18n)

- All visible text in templates is wrapped in `{{ i18n "..." }}` tags.
- `i18n/en.json` is generated by `find_missing_i18n_strings.py`. **Never hand-edit it.**
- **Never edit the other-language files** (`uk.json`, `et.json`, and so on). Those come from volunteer translators through Weblate.
- Do not run `setup-pages-for-supported-languages.py` for everyday text or template edits.

## Writing style

- **AlmaLinux** is always one word with a capital A and L in copy. Never "Almalinux" or "almalinux" in visible text (lowercase is correct only in web addresses, file paths, and package names).
- **benny Vasquez** is written with a lowercase b and an uppercase V.
- **No long dashes** (em-dashes or en-dashes) in copy. Use a colon, a period, or parentheses instead.
- **AlmaLinux Day** always uses a colon: "AlmaLinux Day: Tokyo", "AlmaLinux Day: LA".
- Headings use Title Case; bullet points and list items use sentence case.

## Look and feel

- The design system is in `DESIGN.md` (brand colors, buttons, components, conventions). Consult it for any visual change.
- Do not invent new colors. Use the brand color variables, not raw hex.
- Marketing CTAs use the `al-cta-*` classes (`al-cta-blue` is the default; `al-cta-green` only for registration and certification sign-ups). Bootstrap's `btn-primary` and `btn-warning` still appear on application and membership-apply actions, but prefer `al-cta-blue` for marketing CTAs. **Never use `btn-success`**: for a green button use `al-cta-green` within its approved purpose.
- Avoid inline styles (`style="..."`). Styles live in the SCSS files.
- Every image needs short, descriptive alt text. Keep blog header images under 500 KB.

## Where different content lives

- **Blog posts:** start a new post with the Hugo archetype (`hugo new blog/YYYY-MM-DD-your-post-title.md`), which scaffolds the file with the correct front matter pre-populated. See `contributing-blog-posts.md` for the full process (front matter, images, sizing).
- **Events, newsletters, code, and design:** see the "Contributing" sections of `README.md`.
