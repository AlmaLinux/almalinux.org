{{ i18n "How to certify" }} #

  1. {{ i18n "Boot our regular" }} {{ i18n "live media" }} {{ i18n "on the system you want to certify, or run the suite on an existing AlmaLinux installation. Nothing needs to be wiped or reinstalled." }}
  2. {{ i18n "Install the suite with dnf install alma-certify, from the" }} {{ i18n "extras repository" }}{{ i18n ", and run it. Nearly all hardware finishes a certification run in under 10 minutes." }}
  3. {{ i18n "Publish your results to the catalog with a free" }} {{ i18n "AlmaLinux Account" }}{{ i18n ", or keep them to yourself. Everything published goes through review before it appears." }}

{{ i18n "You only need an AlmaLinux Account if you want to publish what you find. If you are not sure what to run, run alma-certify with no arguments and it will walk you through the options." }}

{{ i18n "Certifying software" }} #

{{ i18n "Software certification works differently, because there is no suite to run against an application the way there is against a machine. A software listing names the AlmaLinux major versions a product is certified for, and each of those versions carries its own evidence." }}

{{ i18n "If you publish software, list your product in the catalog, cite the AlmaLinux releases it supports, and submit your testing data. If your company is not in the catalog yet, you can add it from the same form." }}

{{ i18n "If you use software, sign in and confirm that a product works on the release you are running. Confirmations are counted one per person per release, and they sit alongside a publisher's certification. If you are running a product on a release its publisher has not cited, you can report that too." }}

{{ i18n "Validation levels" }} #

{{ i18n "Every entry in the catalog includes the level of validation, which tells you who ran the test. Validations are cumulative: a vendor, the AlmaLinux OS Foundation, and any number of community members can all attest to the same listing, and each one adds to the confidence in it." }}

  • {{ i18n "Community validated" }}

    {{ i18n "Submitted by a community member. For hardware it is backed by real certification suite data, the same suite the vendors and the Foundation run. For software it is a confirmation that a product works on a given release. Community validation is just as valuable to us as a vendor listing." }}

  • {{ i18n "AlmaLinux validated" }}

    {{ i18n "Tested and certified directly by the AlmaLinux OS Foundation." }}

  • {{ i18n "Vendor validated" }}

    {{ i18n "Published by the vendor and backed by their own testing data. This is the path for hardware and software providers who want to state compatibility officially." }}

{{ i18n "Certification here is a statement about compatibility. It says that AlmaLinux runs correctly on a piece of hardware, or that a piece of software runs correctly on AlmaLinux. This is not a regulatory or security certification. AlmaLinux OS 9.2 has those separately: FIPS 140-3 validated cryptographic modules and a Common Criteria certification." }}
